# Contributing to Nyveth Projects

Thank you for your interest in contributing to Nyveth open-source software.

Nyveth develops independent software tools, engineering infrastructure, intelligent systems, and applications. Individual projects maintain their own architectures, design philosophies, and testing standards.

---

## 1. General Principles

- **Thoughtful & Focused:** Keep pull requests focused on a single change or fix.
- **Maintain Integrity:** Do not introduce breaking changes or unnecessary dependencies without prior discussion.
- **Local Validation:** Always run the project's test suite and linters before opening a Pull Request.

---

## 2. Contribution Workflow

1. **Fork & Branch:** Fork the respective repository and create a branch:
   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b fix/your-fix-name
   ```
2. **Commit Conventions:** Write clear, descriptive commit messages outlining what was changed and why.
3. **Verify Locally:** Execute local builds, linting checks, and unit tests.
4. **Open a Pull Request:** Fill in the Pull Request template completely, providing reproduction steps or verification proof.

---

## 3. Project-Specific Overrides

Individual repositories within the Nyveth organization may specify tailored contribution guidelines in their local `CONTRIBUTING.md`. Where repository-level guidelines exist, they supersede these general organization defaults.
